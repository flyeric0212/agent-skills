---
name: grill-me
description: 通过结构化分批访谈对齐计划，减少问答轮数。
---

用户希望通过对话澄清计划、方案或设计。聚焦影响结果的实质性决策，用紧凑批次提问，保持节奏。

## 工作流程

### Phase 1: 输出全景 → 用户确认

分析 topic、代码库、上下文后，输出依赖感知的决策批次计划，然后等待用户确认、纠正或补充。

```
本轮 grill 涉及以下决策，已按依赖关系分批：

第 1 轮（独立）       : API 路径设计, 异常策略, 分页方式
第 2 轮（依赖第 1 轮）: 请求/响应结构, 权限粒度
...

这个范围对吗？有没有遗漏或依赖关系不对的？
```

保持简洁：一行依赖说明加一行决策列表即可。用户确认前不进入下一阶段。

### Phase 2: 分批推进

按批次顺序推进，每个 batch 用表格呈现决策（推荐 + 选项），结尾询问确认。

示例表格：

```markdown
第 1 轮 — 独立决策：

| 决策 | 推荐 | 选项 |
|------|------|------|
| API 路径前缀 | /api/v1 | /api / /api/v1 / /api/v2 |
| 异常策略 | 全局异常处理器 | Controller 内 / 全局 |
| 分页方式 | Cursor 分页 | Offset / Cursor |

以上没问题吗？
```

### 过程中随时纠偏

发现遗漏决策、依赖错误、范围变化时，更新剩余批次计划，继续推进。

### Phase 3: 最终汇总

所有批次确认完毕后，输出完整决策清单（同 Phase 2 表格格式，Options 列改为结论），让用户做最终确认。

### 快速退出（可选）

用户说"剩下的按推荐走"或类似意思时，立即执行。

## 硬性规则

- 提问前先从上下文、代码、文档或搜索中确认可自行验证的信息；不要让用户重复已知或可安全推断的内容。
- 只询问会改变计划、设计、范围、实现或输出的决策；不问无执行影响的偏好问题。
- 使用能保持真实依赖顺序的最少轮次；彼此独立的决策默认合并，除非单轮难以清晰回答。
- 每个决策必须包含推荐答案和具体备选项；不提出开放式问题。
- 用户接受推荐、表示“按默认/推荐继续”或给出等价指令时，立即停止访谈并继续执行。
